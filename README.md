# expenseful

Android-first, no-bank-integration expense tracker built around a coin jar
visual metaphor.

## Stack

- **State management**: Riverpod
- **Local storage**: Drift (SQL, sqlite under the hood)
- **Navigation**: go_router
- **Auth**: Firebase Auth (identity only — optional, no cloud data sync)
- **Charts**: fl_chart

## Getting started

1. Install dependencies:
   ```
   flutter pub get
   ```

2. Generate Drift + Riverpod codegen (needed for `database.g.dart` and any
   `@riverpod`-annotated providers — re-run this any time a table or
   annotated provider changes):
   ```
   dart run build_runner build --delete-conflicting-outputs
   ```
   For active development, keep it watching in the background:
   ```
   dart run build_runner watch --delete-conflicting-outputs
   ```

3. Add font files to `assets/fonts/` (Baloo 2, Plus Jakarta Sans, Space
   Grotesk — `.ttf` files matching the weights declared in `pubspec.yaml`).
   The app will fail to build without these until they're added, since
   they're referenced in `pubspec.yaml`.

4. Firebase setup (once package name is finalized):
   ```
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```
   This generates `lib/firebase_options.dart`. Then uncomment the
   `Firebase.initializeApp(...)` lines in `lib/main.dart`.

5. Run on a connected device/emulator:
   ```
   flutter run
   ```

## Folder structure

```
lib/
  app/                  # theme.dart, router.dart, main.dart entry wiring
  core/                 # shared constants, extensions, utils
  data/
    local/               # Drift database + generated code + DB provider
    models/              # domain models (if distinct from Drift row classes)
  features/
    onboarding/           # Welcome splash, Currency setup
    home/                 # Dashboard, animated coin jar
    add_expense/           # Add Expense sheet
    recurring/             # Recurring confirmation sheet
    history/               # History screen, Expense detail sheet
    insights/               # Charts
    export/                 # Export sheet
    settings/               # Settings screen (incl. optional sign-in)
  shared_widgets/         # reusable UI components (chips, pickers, etc.)
```

Each feature folder has its own `presentation/` (widgets/screens) and
`providers/` (Riverpod state) subfolders — keep feature code contained
there rather than reaching across features directly.

## Open product decisions

Tracked here so they don't get lost — update as they're settled:

- [x] Recurring expenses: auto-log vs. confirm — resolved as a **per-rule
      toggle** (`RecurringRules.autoLogEnabled`), not a global setting.
- [ ] Export format: CSV, PDF, or shareable image summary.
- [ ] Currency/locale: device-detected vs. manual (`AppSettings.localeMode`
      column already supports both — UI/logic not yet built).
- [ ] Package name / Application ID — required before Firebase setup.
- [ ] Min SDK — proposed default: 23 (set in `android/app/build.gradle`
      once the Android project is generated by `flutter create`).

## Notes on the data layer

- All data is local-only via Drift. Firebase Auth provides identity only;
  there is no Firestore sync in v1. If cloud sync is added later, treat it
  as a separate architectural phase (e.g. Drift-as-cache + remote source of
  truth), not a small addition.
- Schema version starts at 1 (`AppDatabase.schemaVersion`). Any future
  column/table change must bump this and add a migration step in
  `AppDatabase.migration` — never edit an existing table definition without
  also writing the migration, or existing users' local data can break on
  upgrade.
